# 02 Domain model

## 1. Identifiers

| Identifier | Format | Stability | Produced by |
|---|---|---|---|
| `resort_id` | lowercase slug, e.g. `whistler-blackcomb` | permanent | catalog |
| `bundle_id` | 64 lowercase hex chars, SHA-256 of the stored (gzipped) bundle bytes | immutable per bundle | pipeline `build` |
| `node_id` | `n<osm_node_id>` for OSM nodes; `v<12 hex>` for synthetic vertices (hash of rounded lon,lat,ele and source way) | stable across bundles while the source node exists | pipeline |
| `edge_id` | `w<osm_way_id>:<k>` where `k` is the 0-based split ordinal along the way's node order; a run drawn from a trail map has a way id of 9×10^15 or more (`05-PIPELINE.md`, `add_runs`) | stable while the way's split points are unchanged | pipeline |
| `group_id` | `trail:<slug>` or `lift:<slug>`; slug from the reconciled manifest identity | stable across bundles (manifest-owned) | pipeline `reconcile` |
| `rendezvous_id` | slug, e.g. `roundhouse-lodge`, manifest-owned | stable across bundles; removal invalidates meets | pipeline `reconcile` + review |
| `meet_id` | UUID v4 generated by the proposing client | | client |
| `descent_id` | UUID assigned by server; `content_hash` (SHA-256 of normalized track) is the dedup key per owner | | client/server |
| `conditions_id`, `status_id` | bigint row ids | | server |

Rules:
- Nothing hashes a decoded model to make an identity. `bundle_id` is the hash of bytes.
- Clients compare identities by string equality only.
- A meet references `rendezvous_id` + `resort_id`; `bundle_id` on a meet is advisory.

## 2. Resort bundle (schema_version 1)

Storage: `resort-bundles/<resort_id>/<bundle_id>.json.gz`, public-read. Gzip container
(RFC 1952) of UTF-8 JSON. The client MUST verify SHA-256 of the downloaded bytes equals
`bundle_id` before decompressing, MUST reject decompressed size over 64 MB, and MUST run
`BundleIntegrity.validate` before use.

```jsonc
{
  "schema_version": 1,
  "resort_id": "whistler-blackcomb",
  "name": "Whistler Blackcomb",
  "timezone": "America/Vancouver",          // IANA; all local-time logic uses this
  "bbox": [minLon, minLat, maxLon, maxLat],
  "center": [lon, lat],
  "status_mode": "live" | "scheduled_only",
  "status_aliases": { "<provider>": { "<provider name>": "<group_id>" } },
  "source": {
    "extract_id": "osm-2026-11-01T06:00Z-whistler-blackcomb-ab12cd",
    "osm_extract_at": "2026-11-01T06:00:00Z",
    "openskimap_at": "2026-10-28T00:00:00Z",
    "official": ["https://..."],
    "manifest_version": 7
  },
  "built_at": "2026-11-02T10:11:12Z",
  "pipeline_version": "1.0.0",
  "nodes": [
    { "id": "n123", "lon": -122.9, "lat": 50.1, "ele_m": 1850.0,
      "kind": "junction" | "lift_bottom" | "lift_top" | "base" | "landmark" }
  ],
  "edges": [
    { "id": "w987:0", "from": "n1", "to": "n2",
      "kind": "run" | "lift" | "connection",
      "group": "trail:franzs-run",            // every run and lift edge belongs to a group
      "name": "Franz's Run",
      "difficulty": "green" | "blue" | "black" | "double_black" | "park" | "unknown",
      "geometry": [[lon, lat, ele_m], ...],   // source geometry, from→to order
      "length_m": 812.4, "vertical_m": -143.2, "grade_max_deg": 21.5,
      "groomed_default": true | false | null,
      "moguls": true,                          // optional, runs only: piste:grooming=mogul; omitted otherwise
      "aspect_deg": 135.0,
      "one_way": true,
      "approximate": true,                     // optional, runs only: drawn from a trail map (05 add_runs)
      "lift": {                                // present iff kind == lift
        "type": "chair" | "gondola" | "tbar" | "magic_carpet" | "rope_tow" | "cable_car",
        "ride_s": 540, "capacity_pph": 2400,
        "operating_hours": [ { "days": [1,2,3,4,5,6,7], "open": "08:30", "close": "15:30" } ],
        "queue_entry": "bottom" | "both"       // both iff bidirectional (oneway=no in source)
      }
    }
  ],
  "groups": [
    { "id": "trail:franzs-run", "kind": "trail" | "lift", "name": "Franz's Run",
      "difficulty": "blue", "edge_ids": ["w987:0", "w987:1"], "official": true,
      "approximate": true }                    // optional: every run of the trail is drawn
  ],
  "rendezvous": [
    { "id": "roundhouse-lodge", "node_id": "n555", "kind": "lodge" | "lift_base" | "lift_top" | "junction" | "landmark",
      "name": "Roundhouse Lodge", "confidence": 0.95, "quality": 0.9,
      "amenities": ["food", "restrooms", "indoor"] }
  ],
  "integrity": {
    "lift_tops_reaching_base": 1.0,
    "rendezvous_reachable_from_all_lift_tops": 1.0,
    "orphan_edge_share": 0.004,
    "unnamed_run_share": 0.02,
    "flags": [ { "code": "lift_exit_dead_end", "edge_id": "w444:0", "lon": 0, "lat": 0, "note": "..." } ]
  }
}
```

Optional keys added later (`moguls`, pipeline 1.5.0) leave `schema_version` at 1: a
client ignores keys it does not decode, and reads a missing optional key as its
default (`moguls` false).

Constraints enforced by `BundleIntegrity.validate` (fail closed):
- Every `from`/`to` exists; every group's `edge_ids` exist and have `group == id`;
  every rendezvous `node_id` exists.
- Lift edges have `lift`; run edges have `vertical_m <= 0` unless `kind == connection`.
- Geometry first and last points coincide with `from`/`to` within 1 m; coordinates in
  bbox; no NaN; `length_m` within 5 % of geometry length.
- `status_mode == live` requires `status_aliases` to cover at least 80 % of the lift groups (the status worker's own rule; lifts it cannot name run on their hours).
- Integrity metrics present and within the publication thresholds in `05-PIPELINE.md`
  (the client checks presence, the pipeline checks thresholds).

## 3. Status

```jsonc
{ "resort_id": "...", "observed_at": "...", "expires_at": "...",  // expires_at = observed_at + 75 min
  "source": "epic" | "mtnpowder" | "liftie" | "scheduled",   // liftie reports lifts only
  "groups": { "lift:peak-express": "open" | "closed" | "hold" | "scheduled",
              "trail:franzs-run": "open" | "closed" },
  "groomed": ["trail:franzs-run"],
  "wait_minutes": { "lift:peak-express": 6 } }                 // live queue, optional
```

- `StatusFreshness`: `fresh` if now < `expires_at`; `stale` if within 6 h after;
  `unavailable` otherwise or if no row.
- `scheduled` for a lift means "no live information; use operating hours". A lift
  group missing from `groups` means the same; a `source: scheduled` row has empty
  `groups`. A trail group missing from `groups` has unknown status.
- For `status_mode == scheduled_only` the server still publishes a row every hour with
  `source: scheduled` derived from operating hours, so clients have one code path.
- `wait_minutes` (migration 0014) is the provider's queue at `observed_at` for lifts that
  are `open` or `hold`, at most 240 min; several vendor names feeding one group take the
  longest. Epic and MtnPowder report it, Liftie does not. The row keeps a reported 0;
  the solver reads 0 as unknown. A lift with no entry, a row
  without the key and a row that is not `fresh` all mean "no live wait": the solver
  prices the modelled queue exactly as before (`06-SOLVER.md` section 2).
- Status is applied by the solver as cost (closed = untraversable) and by `MapScene` as
  feature-state. It never changes graph topology.

## 4. Conditions

```jsonc
{ "resort_id": "...", "observed_at": "...", "expires_at": "...",   // + 90 min
  "source": "open-meteo",
  "current": { "at": "...", "temp_c": -4.0, "wind_ms": 6.1, "gust_ms": 11.0,
               "visibility_m": 8000, "cloud_pct": 70, "snow_24h_cm": 12.0,
               "precip_mmh": 0.4, "weather_code": 71 },
  "hourly": [ { "at": "...", ...same fields... } ],                  // next 24 h
  "elevation_m": 685,                 // height the forecast is for; null on older rows
  "recent": [ { "at": "...", "temp_c": -0.8, "cloud_pct": 3 } ] }    // past 24 h, oldest first
```
A sample may also carry, each optional (absent on older rows, and when the forecast
model lacks it): `wind_dir_deg` (where the wind comes from), `dew_point_c`,
`cloud_low_pct`, `temp_850_c` and `temp_700_c` (air temperature at about 1,460 m and
3,010 m), `snow_depth_cm`, `snow_72h_cm`. A reader without one falls back to the
resort-wide reading. Wind direction interpolates the short way round the compass.
Interpolation rule (invariant I-05): linear across a normal gap; at an edge or a
missing interval hold the nearest sample for 1 h, fade to `current` over 30 min, then
use `current`.

## 5. Skier profile and pace model

```swift
public enum Ability: String, Codable, Sendable { case beginner, intermediate, advanced, expert }
public enum Discipline: String, Codable, Sendable { case ski }
public enum EquipmentType: String, Codable, Sendable { case allMountain = "all_mountain", carving, freeride, park }
public struct Equipment: Hashable, Codable, Sendable {
  public var discipline: Discipline
  public var type: EquipmentType
  public var lengthCM: Int?                     // 60...220
  public var waistMM: Int?                      // skis only, 55...140
}
public enum Avoidance: String, Codable, Sendable { case ungroomed, flats, park, surfaceLifts = "surface_lifts" }
public struct SkierProfile: Hashable, Codable, Sendable {
  public var userID: UUID
  public var ability: Ability
  public var maxDifficulty: Difficulty          // hard gate
  public var baselineSpeedMS: [Difficulty: Double] // green/blue/black/double_black/park
  public var liftBoardingPenaltyS: Double
  public var prefersGroomed: Bool
  public var equipment: Equipment?              // pace
  public var avoid: Set<Avoidance>              // hard gates
  public var maxPitchDeg: Double?               // hard gate, 10...45
  public var heightCM: Int?                     // private; only ever set for the device's own skier
  public var weightKG: Int?                     // private; only ever set for the device's own skier
}
public struct PaceModel: Hashable, Codable, Sendable {
  public var ownerID: UUID
  public var computedAt: Date
  public var difficultyFactor: [Difficulty: Double]   // multiplicative vs baseline, shrunk
  public var edgeFactor: [EdgeID: Double]             // multiplicative vs difficulty estimate, shrunk
  public var stopsPerKm: Double                       // learned stop rate, used for elapsed time
}
```
`PaceModel` is produced only by the server (`pace_recompute`, `08-ACTIVITY.md` section 4.2). Friends read it through
the `pace_models_friend_read` view; it contains no raw positions.

### 5.1 Equipment, body and limits: what is stored and why

Every field below changes a route or an ETA. The exact rules are in `06-SOLVER.md`
section 2 ("limits" and "equipment").

| Field | Stored as | What the solver does with it |
|---|---|---|
| Hardest run | `profiles.max_difficulty` | Hard gate: a harder marked run is never routed ("never a black"), except on the labelled easiest way down for a skier with no way down within their level (`06-SOLVER.md` section 1, I-07). Set by the skier, independent of ability. |
| Steepest pitch | `profiles.max_pitch_deg` (10–45, null = none) | Hard gate: a run whose steepest pitch is over the limit is never routed. |
| Avoid: ungroomed | `profiles.avoid` | Hard gate on runs known to be ungroomed (today's grooming report, else the bundle default). This is where moguls and glades are found in a bundle (a mogul run is also flagged `moguls`, which only the run card reads). |
| Avoid: flats | `profiles.avoid` | Hard gate on runs of 100 m or more averaging under 3° (cat tracks and traverses). |
| Avoid: terrain park | `profiles.avoid` | Hard gate on `park` runs. |
| Avoid: surface lifts | `profiles.avoid` | Hard gate on boarding a T-bar, rope tow or carpet. |
| Discipline | `equipment.discipline` | Always `ski`: the app offers skis only and writes `ski`. Gear an older build saved as `snowboard` (the column still accepts it) is decoded as `ski` with its length dropped, for the owner and for a friend alike, so it is shown, edited, routed and saved back as skis. The solver has no snowboard rules. |
| Type | `equipment.type` | Small pace effect by terrain (carving on groomed, freeride in fresh snow off-piste, park in the park) and the float value when no waist is given. |
| Waist width (skis) | `equipment.waist_mm` | Pace: narrow is faster on groomed, wide is faster in fresh snow off-piste, at most ±3 %. |
| Length | `equipment.length_cm` | Pace, with height: long for the skier is steadier on moderate groomers and slower in steep or ungroomed terrain, short the reverse, at most ±3 %. |
| Height | `profiles.height_cm`, private | Only as the yardstick for length. |
| Weight | `profiles.weight_kg`, private | Pace on flat runs: a heavier skier carries more speed (∝ mass^⅙, at most +6 % / −7 %). |

Considered and left out: snowboards (PowderMeet routes skiers; importing a
snowboarding day still counts its runs, `08-ACTIVITY.md`), and separate mogul and
glade choices (the bundle flags only the runs the map tags as mogul runs, and has no
glade flag; `ungroomed` covers both).

Two more `equipment` keys are stored for display only; the solver never reads them:

| Field | Stored as | What it does |
|---|---|---|
| Ski model | `equipment.ski` (skis only) | The key of a ski in the app's bundled catalog (`atomic-bent-110`). Picking one fills type and waist width, which stay the routing source of truth and can be edited after. The server checks the key's shape only; a key this build does not know draws as the house ski. The brand artwork is kept in its own asset catalog, `SkisTopsheets.xcassets`. Every catalog model stays on offer; one whose image is switched off (`SkiCatalog.usesBrandArtwork`) or missing (that folder deleted) is drawn by the app as a brand-free topsheet in the model's accent with its name. |
| Skin | `equipment.skin` | Not a choice: a catalog ski is drawn with its own topsheet and custom gear with the house ski. A stored skin (`house`, or a pattern name older rows carry) is read and ignored, and never written. |

Height and weight are private (`04-SCHEMA.md` section 3): a friend's phone never has
them and prices that friend's legs without them. The two phones can therefore
disagree about one skier's pace by the bounded few percent those two fields carry;
the ETA a meet shows for a skier is always the one that skier's own phone computed.

## 7. Presence

`presence`: `user_id, resort_id, lon, lat, accuracy_m, speed_ms, heading_deg,
captured_at (sender clock), received_at (server), app_build`. One row per user.
Positions are shared with the set defined in DECISION 7. TTL 15 min for display;
`captured_at` must be greater than the stored one (monotonic) or the update is dropped.

Where a position is on the map (`PlaceLocator`, DescentKit) labels a friend's marker, chip
and card and the user's own profile card: "On Pika's Traverse", "Riding Peak Express", or
just the resort. It reads one position (coordinate, accuracy, speed, heading, time) with
the previous answer for the same person, built once per bundle into a grid over every
run, connection and lift line:
- A line counts within 25 m, plus half the reported accuracy, at most 50 m. A fix less
  accurate than 100 m names nothing.
- Riding a lift: within that distance of the lift line and moving up it (within 40°,
  at least 0.7 m/s, no faster than 1.5 times the lift's own speed plus 1 m/s). The
  direction is the phone's course, or else the move from an earlier position of the
  same person at most 120 s old and at least 10 m away, which the answer carries
  forward, so fixes a second apart on a slow chair still give one. Standing at a base
  station is not riding, and a gondola ridden down shows the run beneath it: at skiing
  speed the two look the same.
- Otherwise the previous answer holds while its line is within 40 m (or the widened
  distance), so the label does not flicker between parallel runs. A held lift answer
  also needs the position more than 20 m from both stations and not moving off the
  lift's way, so a stopped chair keeps its riders and getting off ends the ride.
- Otherwise the nearest run or connection. A named connection reads as a run.
- Names come from the line's group, else the edge. The answer is nil off the map, when
  the chosen line is unnamed (never the next named line further away), or when unsure.

## 8. Descent (activity)

```
descent_id, owner_id, source: live | slopes | gpx | tcx | fit | healthkit,
started_at, ended_at, content_hash (unique per owner),
track: compressed polyline with timestamps and elevations (bytea, gzip of JSON),
resort_id (resolved by bbox vote), device, app_build,
stats (optional, derived on the importing phone, replaced by a re-import of the same bytes):
  {vertical_m, distance_m, top_speed_ms, avg_speed_ms, trail_name, difficulty, matched,
   resort_name, local_day (yyyy-MM-dd at the resort), source_app,
   pace {<difficulty>: {moving_s, length_m}}, matcher_version}
```
A descent restored from an older PowderMeet backup has a track with no points (that
format keeps no GPS; `08-ACTIVITY.md` section 2.3).
`stats` exists because the server has no parser: the history, the lifetime totals and
pace calibration are all drawn from it without downloading a track. Every key is
optional; a value the phone could not measure is absent, never zero. `trail_name` and
`difficulty` are the run the descent was mostly on in the bundle it was matched to;
`matched = false` means the name is only the nearest run. `pace` is the trustworthy
moving time and distance per difficulty from the match (`08-ACTIVITY.md` section 4).
`matcher_version` is the `MatcherVersion` that named and paced it, absent when no map
was used (`08-ACTIVITY.md` section 3).
`descent_matches` (derived, re-runnable): `descent_id, bundle_id, matcher_version,
matched [{edge_id, enter_at, exit_at, moving_s, length_m, difficulty?}], coverage, confidence`.
`difficulty` is the edge's in the bundle it was matched to; the server, which reads no
bundle, keeps it on `pace_observations` for the pace model.
`source = live` is a run the phone recorded itself (`LiveRunBuffer`); `healthkit` is one
read from an Apple Health workout route. Both go through the same segmenter, matching and
`descent_upsert` as a file.

## 9. Time

- All server timestamps are `timestamptz`; all expiries are set by the server.
- The phone sends `captured_at` for fixes and descents only; it never sets an expiry.
- Local time for lift hours and sun uses the bundle's IANA `timezone` through
  Foundation's `TimeZone`; device time zone is never read for routing or rendering of
  mountain time (invariant I-06).
- Solve time is quantized to 60 s buckets (invariant I-13) for caching; display uses
  real time.
